### 关键量法(与既往陷阱的规避)

1. **对比度四拍标定法**(`rtg4-ink.mjs` / `rtg4-navink.mjs`)。先用两拍差分取「前 10% 像素」的做法**被本轮否决**:`diff = 覆盖率 × alpha × |文字色 − 底板|`,把「覆盖率高」与「本地对比大」混在一起,选最大 diff 等于**专挑底板最暗那批像素**,系统性乐观(同一处 DPR1 读 5.18、DPR2 读 10.56)。改为四拍:
   - A = 常态,B = 文字 `color:transparent`(底板),W = 强制纯白且 `opacity:1`,K = 强制纯黑且 `opacity:1`
   - 逐像素 `coverage = (W − K) / 255`(底板项完全抵消,分母恒为 255),取 `cov ≥ 0.95`(收紧档 0.99 / 0.999)为**字形芯**,再逐像素算 WCAG(A 的实渲染色 vs B 的底板色)
   - **红测**:该法在四个已知点与解析预期吻合 —— 中灰窗实测底板 178(解析 177.6)/ 中位 6.22(解析 6.158);纯白带底板 243(解析 242)/ 中位 9.48(解析 9.465);暗态纯底板 12 / 中位 11.81(解析 11.879)。脚本 `rtg4-05-validate.mjs`
2. **磨砂量法**先 `.site-nav > *{visibility:hidden}` 只留 `::before`,对照组注入 `backdrop-filter:none`;底下近纯色时判「不适用」
3. **不开 `reducedMotion:'reduce'`**(会把开场动画清成 none,掩盖真实缺陷);仅静态几何用
4. **状态竞态**:每次测量前后各读一次 `on-light`,不一致标 RACE
5. **废 canvas 配方**(`#x-bg` 的 `getContext` 返回 null)用于亮区;暗区同时跑 live / dead 两组交叉验证,结论一致
6. **冻结时钟**(`getUTCSeconds/Minutes/Hours` 钉死):冒号按秒奇偶做 2s 方波闪烁,四拍之间闪一下会造出 `ink==plate` 的假像素(实测早期 `min=1` 全部来自 clock)
7. **冻结粒子**(拍完场景后令 `requestAnimationFrame` 为 no-op):否则四拍之间粒子在动,「藏字」那拍与「常态」那拍不是同一帧

## 额外发现(与 AC 判定分开)

### A · 横屏菜单的淡出遮罩会让**页面正文透进菜单**(P1,建议修)

`.menu.open` 的 `mask-image` 作用在菜单**自身**上,而菜单背景是不透明的 `var(--x-bg)`。遮罩把底缘 32px 的**背景一起淡掉**,于是身后的页面文案透上来。

- 844×390 截图:语言行 `EN VI 中文` 之下紧贴着页面 hero 副文案 `SHARING SERVICES.`,两者视觉打架。
- 740×360 截图:最后一个可见菜单项是 `NEX`,其下直接是页面文案 `OF DISTRIBUTED COMPUTING POWER` / `SHARING SERVICES.`(经 `src/i18n/en.json` 核实为 `The world's leading provider of distributed computing power sharing services.`)。
- 后果:遮罩本意是「下面还有(菜单)」的信号,实际呈现是「页面漏进来了」。740×360 下最后可见项干净收尾、其下是**另一种字体与语气的文字**,读者更可能判断为渲染错误而不是可滚动提示。
- 证据:`shots/ac5--844x390-.png`、`shots/ac5--740x360--bottom.png`。
- 建议方向(不代拍板):遮罩只作用于菜单**内容层**而非背景层(内容包一层再 mask),或改用底缘渐变覆盖块。

### B · 页脚字标 `.wordmark` 压亮粒子会跌到 1.46:1(AC11-② 的失败点)

- `.wordmark` 是 120px 的 `--x-white` 不透明字标,**不在 `.info` / `.copy` 的护字层里**(护字层是它的兄弟节点);R45 B1 把页脚改回透底后,粒子直接从字标身后穿过。
- 冻结粒子后取 6 个时刻测量:<4.5 的字形芯占比 `0% / 0.34% / 0.15% / 0% / 0.55% / 1.22%`,最差 **1.456**。
- **不是抗锯齿尾巴**:把掩膜从 `cov≥0.95` 收紧到 `0.99` 再到 `0.999`,像素数几乎不变(194→192→190;686→685→682),且这些像素在空间上**成片聚集**(t1 在 x 742–746、t4/t5 在 x 777–780),对应一条亮粒子线穿过字形;底板实测 R 值 110–195(暗页脚本底约 12)。
- 按大字号 AA 门槛 3:1 衡量仍不达标:<3.0 的占比 `0.20% / 0.43% / 0.79%`。
- **两点减轻情节(不用于掩盖结论)**:① WCAG 1.4.3 对「品牌名字标(logotype)」有豁免,`.wordmark` 恰是品牌名;② 该文字不透明且尺寸极大,实景可读性未受影响(见 `shots/wordmark-t1.png`)。
- 判断权交主人:若认可 logotype 豁免则本项可关;若按字面「页脚文字 0 帧 <4.5」则需给字标补护字层或让粒子避开。

### C · 全站最紧的一处对比度只余 ~1–3.5% 裕度(结构性脆弱,非当前缺陷)

出白带下缘存在一个**方向不对称**:进白带的翻色阈值是 `r.top < 条高`(白带顶到条高就翻,比压到文字早 22px);而出白带用 `r.bottom > 条高` —— **向上滚回白带**时,白带下缘要越过**导航条下缘**才翻亮,此时白带已经盖满整条导航(含文字)。该态是「暗态白字 0.78 alpha 压 0.64 暗底板 × 白带」:

- 解析值:底板 = 0.64×12 + 0.36×242 = **94.8**;墨 = 0.78×255 + 0.22×94.8 = **219.8** → WCAG **4.633**(仅比 4.5 高 2.9%)
- 实测(cov≥0.99 / DPR3,6 组配置):底板 94.2–95.6,min **4.542** / 中位 4.586–4.66

**当前判 pass**,但任何一处数值再动都会击穿 AA:`--x-nav-a`(0.64)、`.lang a` 的 `opacity`(0.78)、`--x-light`(#f2f2f2)三者任一变化都会直接改这个数。建议把这三个值焊进机器门(现在 verify 无字号/对比度机器门)。

### D · `verify` 的运行时门偶发红,且红了**没有任何诊断**(P1,建议修)

- 4 次 `npm run verify`:3 次 **8/8 / exit 文件 0**,1 次 **7/8 / exit 文件 2**。
- 那次红的是 `canvas-geometry(运行时)`,stdout 只留下 `[geo] 构建产物…` —— 门在 `npm run build` 之后、打印任何 ✓ 或 `NOT-RUN` 之前就死了。
- **诊断被吞**:`verify.mjs` 的 `spawnSync` 只读 `r.stdout`,**从不读 `r.stderr`**,所以门崩溃时的真实报错永远不进日志。这一类红在门输出面上不可诊断。
- 单独跑该门:`node scripts/gate-canvas-geometry.mjs` → exit **0**,33 路由 × {390,1024,1440,1920,2560} + 断点两侧 {768,860,900,1080,1439} 七判据全过。
- 机制线索(未坐实到具体报错,因 stderr 被吞):该门会 `npm run build` **重建 dist**,而 4399 上正在跑的预览服务同时从这个 `dist/` 供文件;Windows 上「一边清空 dist 一边被另一进程持有句柄」是这类偶发的常见来源。门另有「astro preview 单例 → 复用既有实例」的 stdout 嗅探路径(实测复用到了 4399),也是竞态面。
- 建议方向:`verify.mjs` 把 `r.stderr` 一并纳入 detail;门跑构建时避开正在服务同一 `dist/` 的实例(或直接走 `--reuse 4399 --no-build`)。

### E · AC3「锐度跌幅 ≤10%」的判据本身不是尺度无关量(口径问题,非站点缺陷)

按字面实现「设备像素梯度 ÷ 对比幅度 ×100」得到的跌幅是 **20–27%**(超 10%)。但该式对**同一张位图渲染得越大读数越小**,是度量自身的性质:118 设备px 是 354 源图的 3 倍下采样,157 设备px 是 2.25 倍下采样,两者都是下采样,后者每设备像素跨过的源像素更少,边缘自然摊宽一点。换尺度无关判据(边缘 10–90% 上升宽度)复核:

| 档 | DPR1 | DPR2 |
|---|---|---|
| 1455 / 1700 / 1935(实际) | 中位 **2 / 2 / 2** 设备px(均值 2.64 / 2.79 / 2.96) | 中位 **2 / 2 / 2**(均值 2.40 / 2.56 / 2.79) |
| 上采样对照组 | 1.13× → 均值 3.26;1.98× → 4.53 | 2.26× → 4.99 |

三档**中位数完全相同**,且与真上采样(3–4)清晰分离 → logo 在三档都没糊。AC3 的实质目的达成;建议把该子判据改成边缘宽度或直接以「上采样倍数 ≤1.0」收口。

### F · AC8「≤30%」在部分取样点读到 0.30–0.38(度量敏感,磨砂确实在工作)

15 个有效样本的残留细节比值 0.16–0.38(一阶梯度)/ 0.17–0.38(拉普拉斯),其中 4 个落在 0.302–0.381:`home-zh 黑区`(1455/1440,0.302/0.309)与 `内页 /learn/ y300`(1455/1440,0.381/0.380)。比值随**导航身后内容的空间频率**变化(y300 处身后是几块大卡片的稀疏直边,y700 处是细密文字),不随磨砂开关变化。

**红测坐实**(`rtg4-22`):人为把 `.site-nav` 变成 backdrop root(即 R45 那个 `both`/`backwards` 坑的效果),同一位置比值升到 **1.008 / 1.010 / 1.044 / 1.041** —— 磨砂失效时读数≈1.0,现状读 0.19–0.38,故**磨砂在全部取样点都确实生效**。

### G · 灯箱在手机 DPR2 上是 2.0× 上采样(超出 AC6 口径,属既定设计)

`@media (max-width: 860px)` 显式设 `.cert-zoom img { width: 1160px }`(全出血 + 可平移原件)。390/860 × DPR2 → 绘制 2320 设备px ÷ 1160 固有 = **2.0×**。这是「宁可平移原件也不缩到读不了」的既定取舍,记录备查,不计入 AC6 判定(AC6 只问 1440/1920/2560)。

### H · 404 页 LOGO 不带来路语言前缀(轻微,记录)

`/vi/no-such/` 与 `/zh/nope/` 上,导航区块链接已正确带前缀(`/vi/#how`、`/vi/learn/` …),但 **LOGO 的 href 仍是 `/`**(404 内联脚本的 `if (h === '/') continue` 把它和语言切换链一起跳过了)。从越南语 404 点 LOGO 会落到英文首页。AC7 只要求「区块链接带前缀」,故不计入判定。

### I · 本轮自查纠正的三个**测量仪器**错误(供后续复用者避坑)
