## 方法

全部结论走 Playwright 真浏览器实测,不开 `reducedMotion`,等 `fonts.ready`,滚动用 `mouse.wheel`。

| 项 | 手法 |
|---|---|
| logo 像素几何 | 浏览器 canvas 解码 PNG,逐行/逐列 alpha 与 RGB 直方图 |
| 导航光学对齐 | 「废 canvas」(`#x-bg` getContext 返回 null)后截图,按列窗算各元素墨迹上下沿 |
| 磨砂三态 | 陷阱①:`.site-nav > *{visibility:hidden}` 只留底板;对照组同帧注入 `backdrop-filter:none`;判据 = 水平梯度均值(高频残留) |
| 翻色两态 | 页内 rAF 采样器 230 帧,记 `on-light`/两版 opacity/底板色/文字色 |
| 行遮罩 | 页内 rAF 录制 `.lr-line` 盒 + clip 窗绝对沿 + `Range.getClientRects()` 墨迹沿;起滑前帧截图后**二次确认状态未推进** |
| 护字层 | 平底(废 canvas)与活粒子两种背景各量一次横/竖亮度剖面 |
| 排印尺子 | 9 路由全量采集有直接文本节点的可见元素,按 (字族,字号) 分组列出 (字重,行高,字距,大写) 组合 |
| 压扁检测 | 17 档视口宽 (390…2560) 逐档量 `img` 实际宽高比 vs 母版 |

**两处我自己的误判,已回源推翻,记在此以免误导**:
1. 首轮测到 en/vi 起滑前「漏墨 3178/14728 px」——实为截图落在状态检查之后,拍到了动画中途。墨迹下沿 445.9 恰等于 `.lr-open` 打开后的窗底 446.2,可证。改成「状态检查 → 截图 → 再次状态检查」后三语均为 0。
2. 页脚截图里「看见」护字层的圆角矩形——数值化后内外都是 `12,12,13`,是看图的对比度错觉。

## 逐区观察

### 导航 · 新 logo 的安放

实测(1455 视口,DPR2):导航条 0→74,`<nav>` 内衬 `30px 40px 0`,内容行 30→74(44 高)。

| 元素 | 左 | 右 | 墨迹上沿 | 墨迹下沿 | 墨迹中心 |
|---|---|---|---|---|---|
| logo 图标 | 40 | 80 | 36.5 | 67.5 | **52.0** |
| logo 字标 | 86 | 157.5 | 45.0 | 59.5 | **52.25** |
| 时钟 | 193.5 | 277.3 | 48.0 | 56.0 | **52.0** |
| 链接组 | 821 | 1160 | 48.0 | 56.0 | **52.0** |
| 下载键 | 1288 | 1400 | 30 | 74 | **52.0** |

- **垂直中心线五件全部落在 52.0**(字标 52.25,0.25px 内),这条做得干净。
- 字标与时钟是**中心对齐不是基线对齐**(字标基线 59.5、时钟基线 56.0,差 3.5px)。素材是整体组合标、内部字标又正好居中(wm.cy = 图心 19.5),所以中心对齐是自洽的选择,不算错。
- 间距:左 40(= `--x-pad`,与全站左轨同缘)、logo→时钟 36、时钟→链接组为 `space-between` 余量。素材紧裁无边距,36 就是真光学间距,节奏合理。
- 视觉重量:图标墨迹覆盖率 11.4%、字标 6.9%,对比时钟 3.8% / 链接 3.0% / 实心下载键 46.6%。左端品牌、右端 CTA 两个重心,平衡成立,**没有压过导航其它元素**。
- 压扁:17 档视口宽全部保持 2.9375(DPR2)/ 2.9500(DPR1),`.logo-cell` 的 `flex:0 1 auto` 在任何断点都没被挤到,**零拉伸零压扁**。

### 导航 · 磨砂三态

| 态 | 磨砂 | 对照(无模糊) | 导航下方原始内容 | 削减 |
|---|---|---|---|---|
| 暗区 | 0.028 | 0.256 | 1.767 | **89.1%** |
| 白带 | 0.122 | 0.724 | 2.648 | **83.1%** |
| 内页 | 0.091 | 0.702 | 7.266 | **87.0%** |

上一轮两条根因(开场淡入 `both`→`backwards`、`opacity` 与 `backdrop-filter` 同元素 → alpha 挪进颜色)**确实修好了**,三态一致生效,肉眼回看也对。

### P1-2 · logo 的 1x / 2x 两档宽高比互不相同,且都不等于母版

**类型**:新增缺陷 · **不属已拍板/待拍板项**(素材规格是「等比缩放」,派生两档是我方产出)

**证据**

| 文件 | 尺寸 | 宽高比 | 相对母版 |
|---|---|---|---|
| 母版 `…-dark-master-tight-1412x480` | 1412×480 | 2.94167 | — |
| `public/logo-lockup-dark.png` (1x) | 118×40 | **2.9500** | 横向 **+0.28%** |
| `public/logo-lockup-dark@2x.png` (2x) | 235×80 | **2.9375** | 横向 **−0.14%** |

两档彼此差 0.42%。因为 CSS 是 `height: 40; width: auto`,渲染宽由**被选中的那档**的固有比例决定,实测:

- DPR 1 → 取 1x → logo 宽 **118.00**,时钟 `x=194.0`
- DPR 2 → 取 2x → logo 宽 **117.50**,时钟 `x=193.5`

即同一页面在 1x 屏与 2x 屏上,logo 宽与其后整条 `.logo-cell` 差 0.5px。另外 `width="118" height="40"` 属性给的占位比是 2.9500,与 2x 实际固有比 2.9375 不符,图片落地时有一次 0.5px 回流。
素材 README 的硬要求是「必须等比缩放,不拉伸、不压扁」——我方派生的两档各自偏一点、且互相不一致,严格说两档都不是母版的等比缩放。

**修法(参数级)** —— 最省的一条:**srcset 只留 @2x 一档**
`SiteNav.astro:37-53` 两张 `<img>` 去掉 `srcset` 的 `1x` 候选,`src` 直接指 `@2x`,`width="235" height="80"`:
```
src="/logo-lockup-dark@2x.png" width="235" height="80"
```
CSS `height:40; width:auto` 不动 → 全站唯一比例 2.9375,1x 屏由浏览器降采样(代价 6.7KB→20KB/张)。
若要保两档:两张都按 2.94167 重出并让二者比例相等(如 1x 117.667×40 取 118×40.1 不整数不可行,故实务上建议直接走单档)。删掉的 1x 文件按项目铁律先 Move 到 `.trash/<时间戳>/`。

### P3-2 · mono 16 档在 en/vi 上分两把行高,而 zh 同档四处统一

**类型**:既有值口味(与已交底的「mono 段落四把行高」同族,但那条说的是 12 档)

**证据**

| 路由 | 元素 | 行高 |
|---|---|---|
| / 、/vi/ | `p.sub.x-mono-lg`(首屏副题) | 1.2 |
| / 、/vi/ | 区块 `p`(「Clients pay to run AI workloads…」「The fields below…」) | 1.2 |
| / 、/vi/ | `p.roles.x-mono-lg`(「Engineers, teachers, drivers…」) | **1.5** |
| /zh/ | 以上四处(16.56 档) | 全部 1.5 |
