### #1 `-1.2` · 横屏首屏:**导航压住首行文字(新伤)** + vi / zh 与 >860 宽横屏的下载行仍在折叠线外

上一路的修法**只在英文 × ≤860 宽的三档上自测过**,三个方向各漏一块。

#### (a) 首屏第一行被导航条吃掉 —— 本轮引入

`.hero` 的 `padding-top` 从 `calc(80 * var(--uc))` 收到 44(≤520 档)/ 34(≤380 档),而导航条底沿在 **54**:

| 视口 | `.note` 首行盒 | 导航底 | 被压 | 后果 |
|---|---|---|---|---|
| 844×390 | 44..62 | 54 | **10px** | 首行上半截压在导航板下 |
| 740×360 / 667×375 / 812×375 / 640×360 | 34..52 | 54 | **20px** | **整条首行**都在导航下 |

`elementFromPoint` 逐像素扫(x 取 note 左缘 +40):740×360 上 y=34…50 全部返回 `IMG.lockup`(品牌字标),y=52 返回 `A.logo`,到 y=54 才轮到 `P.note`。截图 `rev3l-note-740x360en.png` 上读到的是「**…ING YOU HIGH-PERFORMANCE COMPUTING SERVICES**」—— 句子的**第一个词被品牌标整个盖住**,三语同型。

|---|---|---|
| 861×390(阈值刚过) | 96px | **118.5px** |

**修法(参数级,已在产物上注入实测,33 组里 30 组通过)**

```css
/* HeroSection.astro:把第 143 行 @media (max-width: 860px) 改成 —— */
@media (max-width: 860px), (max-height: 520px) { /* …原块内容不动… */ }

/* 原第 179 行那块改成(去掉 max-width 上限) */
@media (max-height: 520px) {
  .hero   { padding-top: max(80px, calc(44 * var(--uc))); padding-bottom: max(20px, 5svh); }
  .cluster{ gap: calc(10 * var(--uc)); }
  h1, h1:lang(zh) { font-size: clamp(30px, 13.5vh, 60px); }  /* 关键:字号改挂 vh,不再挂 vw */
}
/* 原第 189 行那块同样去掉 max-width */
@media (max-height: 400px) {
  .hero { padding-top: max(76px, calc(34 * var(--uc))); padding-bottom: max(14px, 3svh); }

```

注入后实测(11 视口 × 三语 = 33 组):**导航压 0/33**,**下载行出屏 0/33,余量 7.0–105.9px**。唯一没过的是 568×320(iPhone 5 一代横屏,en 出屏 64.8),不在本轮视口清单内。

🔴 `h1` 字号必须从 `clamp(40px, 11vw, …)` 改挂 `vh` —— 横屏的约束是**高**不是宽,挂 vw 时 932 宽会算出 65px 的大字塞进 430 的高里,这正是 (c) 的几何根源。

**机器门建议**:`gate-css-shadowed.mjs` 上一路已按「正交 media 条件」补过判据 B3(所以 (a) 这类源序问题这次没复发)。本轮这三条都不是源序问题,是**「修法自测面窄于修法作用面」**:建议在 `verify` 里加一条产物级横屏哨兵 —— 对 844×390 / 740×360 / 667×375 / 896×414 / 932×430 五档 × en / vi / zh 三语断言「`.hero .note` 顶 ≥ 导航底」且「最后一个 `.hero .xbtn` 的 bottom ≤ 视口高」。这是纯几何断言,机器完全测得了,不该靠评审逐档量。

### #2 `-0.6` · vi 行高例外只配了那四组栏卡,**同族其余位置仍在字形重叠**

改用**行感知量法**(先用 `Range` 取每条渲染行的行盒,再在各自窗口里定位本行墨顶 / 墨底),`/vi/` 1440×900 实测:

| `#how .stack .body` | **+1.33** | **4.33** | 5.33 | —(单行) |

**结论:修法有效,而且修前比 0.33 更糟 —— 四组里有三组是真·负值(下一行的叠音符钻进上一行降部)。当前四组全部转正。** 建议以后就用行感知口径,墨带法在 vi 上必然被 intra-line 空隙钉死在 0.33。

| **vi 1440×900** | −16 | — | **−517** | **−1199** | **−5850** |

(正 = 标题先到位;口径 = 标题**末行**滑到位 vs 副题 opacity ≥0.9,单位 ms。)

**vi 在评审指定的 1.5 Mbps 与 0.75 Mbps 两档都还是颠倒的,大标题空白窗口 2.22s / 2.90s。**

**根因:本轮改的是拍子的「起算时刻」,而 vi 卡在更上游的「字体闸」上。** 逐行落位实测(1.5 Mbps):

| 语言 | FCP | **遮罩建好** | 逐行落位 | 副题 |
|---|---|---|---|---|
| en | 908 | **1449** | 2333 / 2499 | 2616 |
| zh | 896 | **1423** | 2353 / 2537 | 2603 |
| **vi** | 924 | **2264** | 2781 / 2947 / **3131** | 2630 |

`fx.ts:672` 是 `document.fonts.load(key, el.textContent)` —— **遮罩要等「这一档字重 + 这一串字」的字体到齐才建**,而 `play()` 的 `setTimeout` 是在 `build()` 里注册的,**字体没到,定时器根本还没创建**;等它到了,`Math.max(0, BEAT_T0 + delay - now)` 已经恒等于 0。所以新锚点在 vi 上**一次都没起作用**。

而 `/vi/` 的字体开销远高于另两语(1.5 Mbps 实测):

| 路由 | 字体文件数 | 传输量 | `fonts.ready` |
|---|---|---|---|
| `/` | 4 | ~55 KB | 1832ms |
| `/zh/` | 4 | ~55 KB | 1859ms |
| **`/vi/`** | **12** | **~173 KB** | **2740ms** |

**A/B 证伪**:在 `/vi/` 上只放行 `be-vietnam-pro-*-500`(标题自己那档)、中止其余 10 个 subset ——

| | 遮罩建好 | 末行落位 | 副题 | 标题领先 |
|---|---|---|---|---|
| A 原样 | 2283 | 3148 | 2615 | **−533ms** |
| B 只放行标题字体 | **1378** | 2694 | 2628 | **−66ms** |

带宽争用一条就吃掉 **905ms**。剩下的 −66ms 是第二个原因:**vi 的大标题是 3 行,en / zh 是 2 行**,多一档约 184ms 的逐行错拍,而副题拍是固定的 1.4s + 0.5s —— 就算字体不争用,vi 也是压线颠倒。

**修法(参数级,两条都要,只做一条不够)**

1. **拆掉字体闸对拍子的耦合** —— 让拍子照常起跑,字体到了再重拆行(`rebuild` 本来就挂在 `fonts.ready` 上了):

```ts
// fx.ts:672 附近 —— 给标题的字体等待加一道上限,超时就先用回退字形建遮罩起跑
const load = Promise.race([
  document.fonts.load(key, el.textContent ?? ''),
  new Promise(r => setTimeout(r, Math.max(0, BEAT_T0 + delay - performance.now()))),
]).catch(() => undefined);
```

2. **把 vi 的字体开销压下来** —— `/vi/` 现在同时拉了 latin / latin-ext / vietnamese 三套 subset × 两个字族 × 两档字重。`latin-ext` 那两个(Space Mono 400/700,共 32KB)在越南语文案里用不到,建议按 `unicode-range` 裁掉;并把标题那档 `be-vietnam-pro-vietnamese-500` 与 `latin-500` 提到 `<link rel=preload>`(实测这两个 1074ms 就下完了,是被后面 10 个挤在同一条链路上拖慢的)。

**附**:0.4 Mbps 下 en 手机也会颠倒(−3450ms),同因(那一档 JS 到得比 3s 兜底还晚)。此档不在评审指定范围,合并在此不单独计分。
