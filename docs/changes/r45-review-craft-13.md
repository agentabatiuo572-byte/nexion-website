## 扣分清单

### #1 页脚品牌记号的护字层是空操作,方洞原样还在 · P1 · 新增缺陷(「已修」不成立)

- **类型**:上一轮判定的缺陷 + 本轮的修法都在,但修法对 `<img>` 无效,渲染结果与修之前**逐像素同构**。不属已排除项(已排除的是「素材形态与配色」,不是「边界」)。
- **证据**:`.mark::before` 用值宽高 = `auto`/`auto`(同组声明在 `.info` / `.copy` 上分别是 640.625×140 与 320.391×50.39);红 scrim 实景 `.mark` 周围零红;2× 实景丝线仍被圆角方边硬切。
- **修法(参数级)**:护字层必须挂在非替换元素上 —— 给 img 套一层壳,样式原封不动搬过去:
  ```html
  <span class="mark"><img src="/logo-mark-dark.png" width="90" height="89" alt="" aria-hidden="true" /></span>
  ```
  ```css
  .mark { position: relative; display: block; width: max(48px, calc(90 * var(--u))); flex: 0 0 auto; }
  .mark img { display: block; width: 100%; height: auto; }
  /* .mark::before 一字不改,即刻生效 */
  ```
- **附带**:本条同时是一条门的缺口 —— 「声明写了 ≠ 画出来了」这类空操作,现有静态门查不到。可焊的机器判据:`getComputedStyle(el,'::before').width !== 'auto'`(有盒才算数),挂在 `::before/::after` 承担视觉职责的元素上。

### #2 修法 ④ 的残留:16 档等宽字仍是两套字身格 · P2 · 新增缺陷(同族没治完)

- **类型**:与 ④ 同一缺陷族(等宽档位下有两个 `letter-spacing`),④ 治了 12 档、漏了 16 档。不在已排除清单。
- **证据**:全站扫描,`/` 与 `/vi/` 同时存在 `16px ls=-0.36`(`#devices .serial`)与 `16px ls=0`(`.x-mono-lg`);`/zh/` 是 `16px ls=-0.36` 与 `16.56px ls=0`。叠卡编舞期两者同屏(区头 vs 卡上序号章)。
- **修法(参数级)**:`DevicesSection.astro:168` 删掉 `letter-spacing: calc(-0.36 * var(--uc))`(全站等宽零字距是仓规,`tokens.css` 三处型类都是 0)。若序号章确需收紧,则把它升为一条**有名字的档**并同步给 `.x-mono-lg`,不要只在一处开例外。

### #3 修法 ⑤ 的残留:#how 头距在 ≤860 又脱队 · P2 · 新增缺陷(同族没治完)

- **类型**:⑤ 治的就是「#how 头距与另五块不同值」,桌面段治好了,窄屏分支原样留着。不在已排除清单。
- **证据**:

  | 861 | 71.75 | 71.75 | 0 |
  | 860 | **60** | 71.67 | −16% |

- **修法(参数级)**:`HowSection.astro` 的 `@media (max-width: 860px) .headrow` 里**直接删掉** `margin-bottom: calc(60 * var(--uc))` 这一行 —— 基础块的 `max(48px, calc(120 * var(--u)))` 会接管,与另五块逐值全等(同一断点内 `.headrow` 的 `flex-direction: column` 与 `gap` 保留)。

### #4 修法 ③ 的 82 档用在 #trust 上读起来是空的 · P2 · 新增缺陷(修法过校正)

- **类型**:③ 把 `#trust` 卡内 gap 从 16 提到 82 求「同族同值」,但同值不同角色 —— 另三组的 82 隔开的是「序号行 → **48 档标题**领衔的内容栈」,`#trust` 的 82 隔开的是「12px 序号 → 12px 正文」,中间没有任何重量件承接。不在已排除清单(已排除的是 4+1 孤儿行,不是 gap)。
- **证据**:1455×1300 实景(`shot-vp-1455x1300-trust.png`)五张卡各有一段 82px 空白,左竖线穿过空白;`#trust` 卡 225.91 高里 82 是空的(36%),但另三组的空白后面接的是 48px 标题,`#nex` 同为 39% 却读得通。
- **修法(需拍板,附推荐)**:
  - **A(推荐)**:`#trust .card` gap 回落到 `calc(24 * var(--uc))` —— 那正是另三组 `.stack` 内部「标题 → 说明」的档,语义上 `#trust` 卡就是一个没有标题的 stack。代价:`#trust` 与另三组的**卡外**尺子仍全等(列距 60、内衬 20、竖线同档),只有卡内一档不同,并在注释里记明「#trust 是无标题栏卡,吃 stack 档不吃 metarow 档」。
  - **B**:保 82,给 `#trust` 卡补一个 24 档的领句(把每卡首句提为标题层)。代价:要改文案结构,超出参数级。
  - **不做会怎样**:白带里五张最「重要」的合规卡是全站唯一读起来空心的一组,越宽越明显(1920 下空白 108.6px)。

### #6 #how 区块内层级齐平,窄屏完全塌陷 · P2 · 既有值口味(② 的落点选择)

### #7 等高线图的线宽脱离 1px 细线尺 · P2 · 既有值

- **类型**:全站细线语言严格 1px(边框实测九处全 1px),但装饰等高线是按卡宽等比缩放 viewBox,线宽跟着放大。不在已排除清单。
- **证据**:同一个 `contour()` 生成器、同一句 `stroke-width="1"`:`#devices` 缩放 0.984 → 渲染 **0.98px**;`#how` 缩放 0.998 → **1.00px**;`#path` 缩放 **1.601** → **1.60px**。#how 与 #path 在白带里上下相邻,线重差 60%,实景可辨(`shot-how.png` vs `shot-path.png`)。
- **修法(参数级)**:`contour` 输出的 `<path>` 加 `vector-effect="non-scaling-stroke"`(一处属性,三个消费点全覆盖)。加完后线宽恒等于 1 画布像素,并与 CSS 边框一样吃画布 zoom,跨断点自动同步。

### #10 语言开关里「中文」的字形芯比 EN/VI 高 38% · P2 · 既有值,且修法与主人定的 12px 下限冲突,需拍板

- **证据**(显字/藏字求差,DPR4,单位 CSS px):EN 与 VI 的拉丁大写墨高 **8.5**(墨顶 7.5、墨底 15.75);「中」「文」墨高 **11.75 / 11.5**(墨顶 6、墨底 17.5)—— 同为 12px,CJK 上下各越界约 1.6px,单字宽 10.5–11.75 对 5.75–7。三件一组的控件里有一件明显更大更重(首屏实景可辨)。
- **修法(需拍板,附推荐)**:
