## 方法

- Playwright(借 `Nexion-uniapp` 依赖),脚本在 `scratchpad/rev2i-*.mjs`。
- 避开本线已知量法陷阱:量磨砂先 `.site-nav > *{visibility:hidden}`、对照组注入 `backdrop-filter:none`;量文字用「显字 / 藏字(`color:transparent`)差值取字形芯」;未开 `reducedMotion`;滚动用 `mouse.wheel` / `scrollTo`;等 `fonts.ready`;亮区走「废 canvas」配方(`addInitScript` 令 `#x-bg` 的 `getContext` 返回 null)。

- 品牌素材按像素核:PNG 头读固有宽高、canvas 读 alpha 包围盒与不透明率,不靠 CSS 声明推断。
- 「已修」一律当待核实断言;上一轮报告里的**判定结论**同样当待核实断言(本轮推翻了其中一条,见 P2-1)。

### P1-1 · 菜单底缘淡出遮罩把菜单**自己的实底**一起擦掉 —— 横屏下页面正文透过菜单

**类型:新增缺陷(本轮改动)**;不属任何已拍板 / 待拍板项。

本轮给手机菜单加了「底缘淡出遮罩 = 下面还有」的信号(`SiteNav.astro:364-365`):

    .menu.open {
      -webkit-mask-image: linear-gradient(to bottom, #000 calc(100% - 32px), transparent);
      mask-image: linear-gradient(to bottom, #000 calc(100% - 32px), transparent);
    }

但遮罩作用于**整个元素的合成结果**,而 `.menu` 的不透明底 `background: var(--x-bg)`(`:342`)就在这个元素上 —— 于是淡出的不只是滚动内容,**连挡住页面的那块实底一起淡掉了**。

实测 844×390 DPR2,菜单开着,取底部 60 CSS px 横条,逐行最大亮度:

| | 行最大亮度(自上而下每 8 设备行) |
|---|---|
| **带遮罩(现状)** | 12.1, 12.1, 12.1, 12.1, 12.1, 255, 255, 200.1, 187.5, **48.1, 18.9, 19.9, 20.9, 24.1, 24.4** |
| 只去掉 mask(同帧) | 12.1, 12.1, 12.1, 12.1, 12.1, 255, 255, 201.1, 193, **12.1, 12.1, 12.1, 12.1, 12.1, 12.1** |

去掉 mask 后那几行是平的 12.1(菜单实底);带 mask 时它们有内容。截图(`scratchpad/rev2i-menu-bleed.png`、`rev2i-menu-844x390.png`)看得很清楚:首屏那句 `SHARING SERVICES.` **压着 EN / VI / 中文 那一行读出来**,两段文字互相穿插。观感不是「下面还有」,是渲染坏了。

**修法(参数级)**:遮罩改成叠加渐变,别动元素自身的 alpha ——

    /* 删掉 .menu.open 上的 mask-image / -webkit-mask-image */
    .menu.open::after {
      content: '';
      position: fixed;               /* 菜单是 inset:0 的定位层,fixed 即贴住其下缘 */
      left: 0; right: 0; bottom: 0;
      height: calc(32 * var(--uc));
      background: linear-gradient(to top, var(--x-bg), transparent);
      pointer-events: none;
    }

### P1-2 · 矮屏压缩块的三条尺寸声明**从未生效**,「不必依赖滚动」的目标在任何真实横屏高度上都没达成

**类型:新增缺陷(本轮改动)**;不属任何已拍板 / 待拍板项。

本轮新加的 `@media (max-height: 520px)`(`SiteNav.astro:368-384`)与它要压的那三条基础规则**在同一个 `@media (max-width: 860px)` 块里、特异度完全相同**,而基础规则写在**它后面**(媒体查询嵌套不加特异度)→ 后写的赢:

|---|---|---|---|---|
| `.menu { padding-top }` | :370 | 24 | **24** ✔ | 基础 `.menu` 在 :341,更早 |
| `.menu { padding-bottom }` | :371 | 16 | **16** ✔ | 同上 |
| `.menu { gap }` | :372 | 14 | **14** ✔ | 同上 |
| `.links { gap }` | :375 | 4 | **6** ✘ | `.links{gap:calc(6*uc)}` :391 |
| `.links a { font-size }` | :378 | 28 | **44px** ✘ | `.links a{font-size:calc(44*uc)}` :395 |
| `.links a { min-height }` | :379 | 44 | **52** ✘ | `.links a{min-height:calc(52*uc)}` :399 |
| `.row2 { gap }` | :382 | 12 | **18** ✘ | `.row2{gap:calc(18*uc)}` :406 |

六条只落地三条,而落地的三条恰好都是 `.menu` 自己的(它的基础规则更早)。后果:

| 视口 | 需要高 | 可用高 | 结果 |
|---|---|---|---|
| 844×390 | **458** | 390 | 溢出 68,下载键整件在视口外 |
| 667×375 | 458 | 375 | 溢出 83 |
| 740×360 | 458 | 360 | 溢出 98 |

**修法(参数级)**:把整个 `@media (max-height: 520px)` 块从 :368-384 移到 `.row2` 收口的 :408 之后(即三条基础规则之后),让它真的赢。移完后按现值重算 390 高:`5×44 + 4×4 = 236`(链)`+ 14`(menu gap)`+ 104`(语言 44 + gap 12 + 下载 48)`+ 40`(内衬 24/16)`= 394`,还差 4 —— 把 :370 的 `padding-top` 由 24 改 **20** 即 390 整。360 / 320 仍需滚动,但那时 P1-1 修好后的淡出叠层已经能正确表达「下面还有」。

### P2-1 · 页脚品牌记号的不透明底板在活粒子场上切出一条硬边;上一轮判它「看不出来」是量错了位置

方形标是 95.4% 不透明的圆角方板(素材规格,母版 95.7%,合规)。页脚 B1 撤掉实底后,它直接压在**流动的粒子丝线**上。实测 1455×900 DPR2,沿记号盒四边逐行取「盒外 8px vs 盒内 8px」的亮度差:

| | 盒外 | 盒内 | 台阶 |
|---|---|---|---|
| 最差行(y=196) | **102.5** | 17.0 | **85.5** |
| 次差(y=180) | 92.8 | 15.9 | 76.8 |
| 板内四角 | 13.6 / 15.0 / 16.0 / 29.9 | | |
| 盒外安静处均值 | 28.5 | | |

也就是说:**丝线扫到记号边缘的那一刻,边界上有 85 级的硬台阶**,而且粒子在动,这条边是活的。1:1 截图(`scratchpad/rev2i-foot-mark-1x.png`)里它就是一块把光场剪掉的黑色贴纸。

**上一轮的结论「深色底板压在 #0c0c0d 上只有约 3% 亮度差,粒子被挡也看不出来」取样取在安静背景上,漏掉了丝线穿越边界这一档**。作为对照,同一记号形态在**导航**里完全没有这个问题 —— 导航有磨砂底板先把背景抹匀,同法实测台阶只有 **5.9**(暗态)/ **6.5**(亮态)。所以这是页脚**透底**特有的。

形态与失误族和上一轮 P1-2 完全一样:B1 撤掉实底 → 逐个补护字层,但那次扫描**只扫了文字,没扫图形件**。

**修法(参数级,不动素材)**:用页脚自己已有的护字层配方给记号也铺一层,让粒子在够到板边之前就淡下去 ——

    .mark { position: relative; }
    .mark::before {
      content: '';
      position: absolute;
      inset: calc(-16 * var(--uc));
      background: var(--x-scrim);            /* rgb(12 12 13 / .9),与板内 13.6–17 同量级 */
      filter: blur(calc(14 * var(--uc)));    /* 与 .info / .copy 同一组参数 */
      z-index: -1;
    }

台阶会从 85 降到 <5(板内 ~16 vs 护字层 ~13),与导航侧的观感对齐。
