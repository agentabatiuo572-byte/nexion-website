## 三、加固点专项(均含反向自证)

### C1 直通密钥 fail-closed
| 场景 | 签发 | 兑换 | 既有 cookie |
|---|---|---|---|
| 生产 + 仓库默认密钥(未轮换) | **503**(文案指明「请先轮换密钥」) | 403 | **451 失效** |
| 生产 + 已轮换密钥 | 200 | 302 | 新 cookie 200 放行;**旧密钥 cookie 仍 451** |
| dev(白名单内) | 200 | 302 | 200 放行 |

🔴 **反向自证**:自行用 `dev-bypass-secret` 计算了一个**本应有效**的 HMAC cookie(`exp = now+29d`)。该 cookie 在生产/`prod` 下 451、在 dev 下 200 —— 证明 451 来自密钥闸而非我的签名算错,排除「恒 451 假绿」。

### C2 模拟头环境白名单
| ENVIRONMENT | `x-geo-sim` 是否生效 | 正对照(真实来源 JP) |
|---|---|---|
| `dev` | 生效 | — |
| `preview` | 生效 | — |
| `production` | **忽略** | 名单含 JP 时无 sim 仍 **451** |
| `prod`(拼错) | **忽略(fail-closed)** | 名单含 JP 时无 sim 仍 **451** |

🔴 关键:旧判据 `ENVIRONMENT !== 'production'` 在 `prod` 拼错时会**放行模拟**;实测新判据拒绝,fail-closed 成立。正对照证明中间件并非「整体失效」造成的假绿。

### L1 HTML 转义
注入 4 向量:`<script>alert(1)</script>`、`" onload="alert(2)`、`<img src=x onerror=alert(3)>`、`' onmouseover='alert(4)`。
产出页真实标签清单仅 `body/main/h1/p/hr`,**携带事件处理器的危险标签数 = 0**,向量全部成为惰性转义文本。
(过程勘误:朴素正则曾报「`onerror=` 裸出现」,回源看上下文为转义后的纯文本,已证伪。)

## 四、AC-G 统计语义(M4 节流下的自定判据)

旧「+N 就是 +N」判据在加固版不成立(M4 = 120 次/分/IP 写入节流)。本轮改用四条判据:

| # | 判据 | 实测 |
|---|---|---|
| 1 | 阈下 1:1 精确 | 单 IP 30 次文档请求 → 入库 **30** |
| 2 | 分桶隔离 | 资产 10 + 放行 10 + 直通 10 → 计数**不变** |
| 3 | 封顶为「下限」而非丢保护 | 单 IP 140 次 → **451 × 140**(拦截本体不受节流影响),统计封顶 **120** |
| 4 | 多 IP 预算独立 | 换 IP 再 20 次 → 120 + 20 = **140** |
| 5 | 口径如实标注 | 面板原文:「同一来源每分钟超 120 次的洪水流量会被采样记录,此时该数字是下限」 |

🔴 结论:**节流只削统计,不削防护**——这是正确的取舍方向。面板三卡数值与 API 真值逐项吻合(今日 7 / 近 7 天 236 / 占比 70.2% / TopN CN 224·RU 12)。

## 六、问题清单

### P2-1 · 状态条第三 chip「屏蔽」仍是硬编码占位,T17 交付未接线
- **现象**:控制台顶部状态条显示 `屏蔽 —`,tooltip 仍为「区域屏蔽规则面板随包⑦交付;此处只读展示」。屏蔽实际开启时该 chip 不变。
- **回源**:`admin/src/shell.tsx:93` 硬编码 `屏蔽 <b>—</b>`;`admin/src/api.ts` 的 `Overview` 接口无 `geoEnabled` 字段。
- **依据**:后台 PRD §149 数据字典 —— `geoEnabled | boolean | 是 | — | 来自 [FEAT-CON12] KV,只读展示`;plan.md T10 裁决记 ——「状态条第三 chip(屏蔽)为诚实占位待 CON12(**T17 接真**)」。T17 已交付,该欠账未随之关闭。
- **性质**:非安全缺陷;属「该有的在不在」维度——前包显式挂账到本包,本包收尾时未回看挂账清单。
- **建议**:`/api/geo` 已返回 `rules.enabled`,状态条数据源补一个字段即可;或由 main 裁决改挂 T20(驾驶舱)一并接。

### 观察项(均非缺陷,列出备查)
- **O1 · 本地 miniflare KV 不观察外部 CLI 写入**:运行中 worker 对 `wrangler kv key put` 写入的值 75s(远超 60s 缓存 TTL)后仍不可见;而 worker 自身写入的值 CLI 可读。**测试面限制,非产品行为**。E3 因此改用「停服注入 → 起服」覆盖。**后续 tester 注意**:D1 的 CLI 写入对运行中 worker 可见,KV 不可见,两者不同。
- **O2 · 浏览器 console 的 409 报错**:护栏触发时出现 `Failed to load resource: 409 (Conflict)`,是浏览器对非 2xx 响应的自动记录,应用已正确处理(渲染二次确认)。非缺陷。
- **O3 · Git Bash CP936 损坏 curl 中文载荷**:经 `-d` 传中文时出站即损坏,存储与服务端呈现一致(worker 忠实处理)。改用 UTF-8 文件 `--data-binary @file` 后,中文拦截页文案端到端正确。**结论:曾疑似的「缓存未失效」不成立**——ASCII 标记实测缓存即时失效(PUT 后下一请求即见新文案)。
- **O4 · E3 兜底的运营语义**:管理员若配置的是非 CN 名单(如仅 VN),KV 读取异常时会静默切换为拦截 CN。此为 PRD E3 字面要求(「退回代码内置默认名单(CN)」),非缺陷,但建议运营知晓该切换方向。
