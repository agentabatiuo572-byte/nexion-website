## 方法

- **视口**:参考站 1440×900(scale=1);我方 **1455×900**(预留 15px 经典滚动条槽后 `--x-vw`=1440、zoom=1,画布 px ≡ 屏幕 px,可 1:1 对读)。另探 1920×1080、2560×1440。
- **手段**:DOM 几何 + 计算样式(任何模式可信);逐 rAF 采样(首载 / 翻色 / Lenis / 行遮罩 / 视差);MutationObserver 计时(打字机);滚轮驱动的叠卡全程扫描;**像素级 A/B 判裁切**(同一页开关 `clip-path` 各拍一张逐像素比);亮区块截图走「废 canvas」配方并回看。
- **自证伪**:参考站本机 rAF 中位 **44–51ms/帧**(≈20 fps),我方 **16.7ms/帧、p90 17.5**(60 fps)。凡时间读数差 ~2×,先量帧率再下结论;曲线用 `cubic-bezier(.16,1,.3,1)` 反解求起拍时刻,消掉采样粒度偏差。
- 参考站只提取机制与数值,定位靠几何 / 标签路径;**本文不含参考站的代码、文案、图片**。
- 脚本:`scratchpad/rev1d-*.mjs`,数据 `scratchpad/rev1d/*.json`,我方截图 `scratchpad/rev1d/s-ours-*.png`。

### 观察 #3(不扣分,供参考)

翻色瞬切的落点:CSS 写的是 `color 0s linear .114s`,与底板 `background-color .25s linear` 同时起算,114/250 = 0.456 → 底板分量 12+230×0.456 = **116.9**,**算术上正好压在交叉点**。4 次实测 3 次落在分量 119(4.20:1),1 次早一帧落 104(3.39:1)。早的那一帧只有 16.7ms,偏差量小于一个刷新周期,**已到 rAF 采样的分辨极限**——我无法区分「真的早翻了一帧」和「我的读数早了一帧」。**结论:声明值正确,不扣分**;若日后想彻底消掉这一帧的不确定性,可把瞬切改成每帧实测底板色、过 L=0.179 才切(与「翻色阈值每帧实测」同一套路),而不是靠固定 delay。

## 给主人的两个拍板项

**① 滑换按钮缓动要不要对齐参考站?**

- 选项 A:改成 `cubic-bezier(.4,0,.2,1)`。代价 = 一行 token,零连带风险;收益 = 消掉最后一处与参考站无理由的曲线差。
- 选项 B:保持 `ease-in-out`。代价 = 这 0.1 分永久留着;收益 = 零改动。
- **我的推荐:A。** 它不是任何人权衡过的决定,只是 CSS 默认关键字,而参考站在同一个交互上有明确取值;肉眼几乎不可辨,所以改它没有「推翻主人调过的数」的风险。
- 不做会怎样:没有功能影响,只在还原度上留一处说不出理由的差异。

**② 导航翻色的「文字瞬切」要不要保留?**

- 选项 A(保持现状):文字在亮度交叉点瞬切。代价 = 手感与参考站的连续渐变不同;收益 = 全程最低对比 ≈4.2:1,12px 导航小字任何滚速都清晰。
- 选项 B(还原参考站):`color .25s linear` 与底板同步渐变。代价 = T3 已证必有一瞬白字与底板同亮度(≈1.18:1),等于用可读性换手感;收益 = 手感 1:1。
