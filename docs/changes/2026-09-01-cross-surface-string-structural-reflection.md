# 结构性反思:跨面传字符串,消费方靠猜

> 触发:同型第四次(全在 2026-09-01 这一个会话内)。按全局铁律「同一错误踩第二次 = 停手做第一性原理反思」,
> 本文写完才允许继续改。触发时三路独立验收里第一路(界面实景)已回报,另两路在跑,被审文件处于冻结期。

## 四次实例

| # | 现场 | 产出方发的 | 消费方认的 | 后果 |
|---|---|---|---|---|
| 1 | 高敏字段判据 | `diffPaths` → `skus[0].priceUSD`(方括号+下标) | `skuFactRe` → `skus.<键>.`(点号) | 产品卡价格**从上线第一天起就没被保护过**,七轮验收全绿 |
| 2 | 界面文案门判据② | TSX 源码里的字符串字面量 | 「像机器词的字符串就报」 | 26 处全误报,含 import 说明符、CSS 值、**映射表的键本身** |
| 3 | 「去修复」定位 | 校验器 → `skus.phone.tagline.en`(点号+id) | `data-field` → `skus[0]`(方括号+下标) | 九条红项里八条点过去停在页顶;**门只验「有没有消费者」,不验「消费者找不找得到」** |
| 4 | 发布失败原因 | 服务端 → `上线核验未通过:内容摘要对不上(期望 3f9a…,实际 缺失)` | `splitFailReason` → 「没有中文就是技术输出」 | 中文句子里嵌 hex 摘要,整句过关,**壳顶红条与驾驶舱把摘要原样印给运营** |

## 四问

### ① 拆到不可再拆:最小成因是什么

不是「某个正则写错了」。四次的共同结构是:

> **产出方把结构化的事实拍扁成一个字符串,消费方再去猜它的结构。**

- 路径:「哪个 SKU 的哪个字段」本来是 `(id, field)` 两个值,被拍成 `skus.phone.tagline.en`;
  另一个产出方把同一件事拍成 `skus[0].tagline.en`。两个字符串描述同一件事,**但没有任何东西规定该拍成哪种**。
- 失败原因:「这次为什么失败」本来是 `(种类, 门名/明细)`,被拍成一句话;
  消费方要把它拆回去展示,只能靠「有没有中文」这种字面特征猜。

一旦拍扁,**信息就丢了**——而丢掉的恰恰是消费方需要的那部分。消费方于是发明一个字面规则去还原它,
那个规则**必然只对当下见过的样本成立**。

### ② 为什么前三次的修法没挡住第四次

前三次我都在**同一层**修:把消费方的判据改成能认当下这个产出方的写法。

- 第 1 次:让判据同时认点号和方括号 → 只覆盖了我当时手上那两个产出方;
- 第 2 次:换成「三元里人话与机器词并列」→ 判据变可靠了,但仍是字面规则;
- 第 3 次:给页面加 `data-field` → 加的标记本身又是拍扁的字符串,又对不上。

**每一次都是给猜的规则打补丁,没有一次动过「为什么要猜」。** 这正是「修法必须落在比上次更强的层」被违反的样子:
三次全在词法层。

### ③ 同族还有几个(穷举,不等下一轮走查发现)

凡「一个面产出字符串 → 另一个面解析它」的地方,全部是同族。已识别:

| 位置 | 产出 → 消费 | 现状 |
|---|---|---|
| `schema/src/diff.ts` → `admin/pages/publish.tsx` `humanPath()` | 改动路径 | 消费方靠正则拆段(已构造性自检,但仍是拆字符串) |
| `schema/src/validators.ts` → 「去修复」链接 → `data-field` | 红项路径 | **对不上(#3)** |
| `schema/src/validators.ts` → `fixLink()` | 红项路径 → 目标页 | 用 `startsWith` 前缀匹配,同样是猜 |
| `worker/src/publish.ts` → `fail_reason` → 四个渲染点 | 失败原因 | **靠字面特征分类(#4)** |
| `worker/src/audit.ts` → 审计页 `target` 列 | 动作对象 | 登录事件塞 IP、其余塞版本号/域名,**同一列混装四五种语义**(界面走查另报) |
| `runner.mjs` 门输出 → `gate` 名提取 | 正则 `/✗\s+([a-z0-9-]+)/` 从日志里抠门名 | 门改一下输出格式就抠错 |

六处,没有一处是「产出方给结构、消费方直接用」。

### ④ 能不能一条不变量或一道机器门根治

能,而且方向是同一条:

> 🔴 **跨面传递结构化数据,不传拼好的字符串让对方猜。**
> 字符串只用于最终显示给人,不用于机器之间传递语义。

落法(按代价从小到大,不必一次做完):

1. **失败原因**(#4,最独立):服务端改传 `{ kind: 'gate' | 'verify-mismatch' | 'crash' | 'timeout', gate?, detail? }`,
   人话映射留在服务端(已有 `GATE_REASONS`),前端不再拆字符串。旧行仍是字符串 → 消费方对无结构的旧行退回现有拆法,
   **但新写入一律结构化**。
2. **路径记法**(#1/#3):在 `schema/` 定一个规范记法与一对互转函数,**产出方各自调用它**;
   焊门:扫全仓出现的 `skus`/`faq` 路径字面量,凡不经该函数生成的即红。
   —— 注意判据要构造性:从种子枚举真实字段,而不是手写一张记法清单(#1 的教训)。
3. **门名提取**(runner):门本身以约定格式输出机器可读的门名(或直接返回退出码 + 门名文件),
   不靠主控从人类日志里正则抠。
