## 方法

- Playwright(借 `Nexion-uniapp` 依赖)真浏览器实测,两站同一套探针脚本、同一口径、同一次运行内成对取值。
- 主量点 1440×900:我方视口 1455(布局宽 1440,画布 zoom 实测 1),参考站视口 1440(缩放矩阵实测 1)。另探 1024 / 1200 / 1512 / 1536 / 1600 / 1920 / 2560 宽,650 / 673 / 700 / 768 / 774 / 800 / 900 / 950 / 1080 / 1100 / 1300 / 1440 高。
- 视觉/动效判据**不开** `reducedMotion:'reduce'`;只有静态几何(区块内衬、栅格、行高、栏内节奏)用 reduce 取。
- 滚动一律 `mouse.wheel`(Lenis),每次取值前等 `fonts.ready` 并做**收敛等待**(轮询 scrollY 至连续多帧不变)。
- 亮区块**不看截图**:粒子 / 叠卡 / 白带一律读 DOM 计算样式与 `getImageData` 像素,不用截图判色。
- 粒子对比用**成对法**:两站丝线几何在同一像素位重合,同一「扫描行 + 相邻两峰」三元组上分别取谷/峰,再逐对相减 —— 4554 组配对样本。
- 首载编排用 `addInitScript` 注入 rAF 采样器,取每个元素起动/到位帧;参考站另做**热重载**一次以消掉冷网络的载入门控。
- 参考站只提取机制与数值,本报告不含其代码、文案与图片。

覆盖:首屏 · 导航 · 黑区陈述 · 叠卡 · 白带卡区 · 页脚 · 动效手感 · 首载编排 · 锚点直达 · 视差位移因子 · 三语 · 10 条路由 · 5 档视口宽 × 12 档视口高。

## 扣分清单

### 1 · P1 · 新增缺陷(本轮 ② 引入)—— 叠卡钉屏定锚取错常数、又加错位置,卡顶比参考站低 141,多数视口切掉品名与价格 · **−1.0**

**类型**:新增缺陷。② 是「朝参考站靠」的拍板执行项,靠的方向与落点都错了,不属「既有值该换个数」,评审可直接判。

**参考站的真实机制(实测)**:钉件 `position: fixed; top: 0`,卡 `position: absolute; top: 133px`。四档屏高(768 / 900 / 1100 / 1300)钉件顶恒 0、卡顶恒 133;卡顶随**画布缩放**走:

| 参考站视口宽 | 1440 | 1512 | 1536 | 1600 | 1920 |
|---|---|---|---|---|---|
| 画布 scale | 1.000 | 1.050 | 1.0667 | 1.1111 | 1.3333 |
| 卡顶(屏幕 px) | **133** | 139.6 | **141.9** | 147.8 | 177.3 |

**「141」的来历**:它落在 1512 与 1536 之间 —— 即参考站在 **~1520–1536 宽窗口**下卡顶的**屏幕像素**读数(133 × 1.06),不是画布常数。画布常数是 **133**。

**我方把它当画布常数,而且加在了钉件上**,卡自身在钉件内的 133 偏移原封未动:

```
DevicesSection.astro:244   top: calc(141 * var(--uc));    /* 钉件 */
                           article.card { top: 133.03px } /* 卡,未动 */
→ 卡顶 = 141 + 133 = 274
```

源码注释(`DevicesSection.astro:239-242`)写的是「**卡顶**恒在 141 …… 导航 74 高,141 留 67 的空」—— 把钉件顶当成了卡顶。实测卡顶到导航下缘的空当是 **200**,参考站是 **60**。

**逐档实测(同一探针,两站同跑)**:

| 视口 | 参考站卡顶 / 卡底 / 被切 | 我方卡顶 / 卡底 / 被切 |
|---|---|---|
| 1366×700 | 126.2 / 627.2 / **0** | 267.2 / 768.2 / **68.2** |
| 1440×768 | 133 / 667 / **0** | 271.2 / 799.6 / **31.6** |
| 1455×900 | 134.4 / 673.9 / **0** | 274 / 808 / 0 |
| 1920×900 | 177.3 / 889.3 / **0**(余 10.7) | 362.5 / 1069 / **169** |

**切掉的是什么**(1920×900,钉屏中):卡的**品名、价格 `$1,199`、以及「217× compute vs phone」整行**全部在折叠线外(实测 `div.cols` 986.4–1042.5 vs 视口 900);1366×700 下价格与倍率行在外。**钉屏期间滚轮只推进叠卡步进,用户没有任何办法把它滚进视野。**

**这次改动把差距改大了**:vh=900 时改前卡顶 183–192(台账自述 192)、参考站 133、改后 **274** —— 差距从 ~50 扩到 141;vh=768 改前 139(几乎正确)→ 改后 274。参考站的 133 正是被调成「133+534=667 装进 768 高屏、×1.333 后 889 装进 900 高屏」的值,我方多出的 141 恰好把这份余量吃光。

**自证「141 恒定」为什么没抓到**:台账的自证是「768 / 900 / 1100 / 1300 四档实测恒 141」,量的是**我方自己刚写进 CSS 的钉件 top**,即用输入验证输入;输出(卡顶)从未与参考站成对量过。

**修法(一行,已运行时验证)**:

```
.devices:global(.decked) .pin { top: calc(141 * var(--uc)); }   →   top: 0;
```

卡自身的 133 偏移就是参考站常数,不需要再加。运行时注入 `top:0 !important` 后实测:

| 视口 | 卡顶(修后) | 参考站卡顶 | 被切 | 导航下留白 |
|---|---|---|---|---|
| 1366×700 | 126.2 | 126.2 | **0** | 52.2 |
| 1440×768 | 131.6 | 133 | **0** | 58.4 |
| 1455×900 | **133** | 134.4 | **0** | 59 |
| 1920×900 | 176 | 177.3 | **0** | 78.1 |

R41 那条「卡片不紧贴导航条」的诉求由参考站自己的数字满足(参考站是 73 高导航 + 60 空当,我方是 74 + 59)。
