## 方法

| 项 | 做法 |
|---|---|
| 文字对比度 | **显字 / 藏字求差**:同一裁切框各截一次(`-webkit-text-fill-color: transparent` 只灭字形填充,不动 currentColor 边框),取差值**前 10% 像素 = 字形芯**,再对芯里**每个像素**单独算「显字色 vs 藏字色」,报 min / p10 / med。不读计算样式(会漏 opacity 稀释),不用 `visibility:hidden`(会连护字层一起灭) |
| 粒子干扰 | 全站扫描用 **A(显)/ B(藏)/ C(显)三连拍**,A≈C 才算数——流光在两拍之间移动的像素直接剔除 |
| 进场动画干扰 | 每个滚动档位先等 `getAnimations()` 全部停,再等 420ms;凡祖先链累计 opacity < 0.985 的元素跳过。**首轮扫出的 30 条低对比全部是淡入 / 打字机 / 行遮罩的中间帧**,逐条回落到稳态复量后清零(见「已核实为动画瞬态」) |
| 磨砂底板 | 量底板时先把 `#site-nav nav` 自身内容隐掉,只留 `::before` |
| 滚动 | Lenis 在管,用 `mouse.wheel` / 拖真滚动条;绝对定位用 `window.scrollTo` 后复核 `scrollY` |
| 翻色竞态 | 读 DOM 与截图**前后各读一次** `on-light` / `flipping`,不一致即作废重取 |
| 视口 | 1440×900、1366×768、2560×1440、390×844、**844×390 横屏**、768×1024;DPR 1 与 2 各跑一遍;桌面另用 `ignoreDefaultArgs:['--hide-scrollbars']` 经典滚动条模式跑一遍 |
| 未开 | 视觉判据全程 **不开 `reducedMotion:'reduce'`**(reduced 单独一轮只查降级) |

脚本:`…/scratchpad/rev3h-*.mjs`(lib / u1 / u1b–f / u1final / u2 / u2b / u2c / u3 / u4 / u5 / ink2 / layout / kbd / mix / lock / hover / btn / slow / motion / anchor / lang / nex / frames / arr2 / seam / rotate / final)。

## 扣分清单

### #1 `-0.6` · U-2 的矮屏压缩是**死 CSS**,横屏手机的下载键仍整块在折叠线下

**类型:新增缺陷(本轮修法未生效)** · 非已拍板项

`SiteNav.astro` 里 `@media (max-height: 520px)` 嵌在 `@media (max-width: 860px)` 内,但**位置排在基础 `.links` / `.links a` / `.row2` 三条规则之前**。媒体查询不加特异度,同特异度按源顺序决胜 → 后面的基础规则整个盖掉压缩值。产物侧已确认(`dist/_astro/Base.wdUn5nTs.css`,被压缩器改写成 `@media (height<=520px)`,其后紧跟 `.links[data-astro-cid-rutobish]{gap:calc(6 * var(--uc)…`)。

844×390 实测计算样式:

| 规则想要 | 实际生效 |
|---|---|
| `.links a` font-size **28px** / min-height 44 | **44px** / 52 |
| `.links` gap **4px** | **6px** |
| `.row2` gap **12px** | **18px** |
| `.menu` padding 24/16、gap 14 | ✅ 生效(它声明在嵌套块**之前**) |

后果:菜单 `scrollHeight 458` vs `clientHeight 390`,**下载键 top=394 / bot=442,整块在视口外**;三个语言链(332–376)倒是进来了,所以「语言链被藏」那一半确实修好了,「下载键被藏」这一半没有。底缘淡出遮罩在,所以「下面还有」的信号是给到了 —— 但 U-2 的目标是「不必依赖滚动」。竖屏旋成横屏(菜单保持开着)同样中招。

**修法(参数级)**:把 `@media (max-height: 520px)` 整块**移到 `@media (max-width: 860px)` 的末尾**(在 `.links a` / `.row2` 基础规则之后);或就地提特异度为 `.menu .links a` / `.menu .row2`。

**已验证有效**:按原意注入压缩值后,844×390 下 `dl-btn` bottom = **384 ≤ 390**,九件全部可见,无需滚动。(667×375 的 iPhone SE 横屏仍差 9 px,若要覆盖需再收 8 px 内衬。)

### #2 `-0.3` · 迟滞窗内导航与白带之间**常驻**一条暗缝

**类型:既有值(R45 迟滞设计的副作用)** · 非已拍板项(拍板的是「底板 = 半透明磨砂」,不是这条缝)

进白带后回滚,`hys = 24` 让导航保持 `on-light` 锁存,而白带顶还在导航下沿之下最多 24 px。屏上就是:**中灰底板(178)→ 0–23 px 纯暗条 → #f2f2f2 白页**。截图 `rev3h-midgray.png`。

1440 实测(白带顶 8260、条高 73.2、翻色点 scrollY 8187):

| 回退量 | on-light | 底板 | 暗缝行数 |
|---|---|---|---|
| 0 px | true | 178 | 0 |
| 8 px | true | 178 | **7** |
| 16 px | true | 178 | **15** |
| 24 px | true | 178 | **23** |
| 28 px | false | 12 | 0(与暗导航连成一片) |

关键在于它是**停住不动也一直在的稳态**,不是过渡帧。用滚轮或拖滚动条在边界停一下就会落进这 24 px。

**修法(参数级)**:`hys` 24 → **0–8**。

**依据**:本轮 U-4 实测里,拖滚动条 ±4 轨道像素 = **±66 文档像素**,远超 24 px 的空间迟滞,而它**仍被压住** —— 说明挡住抖动的是那 400 ms 的时间迟滞,不是这 24 px。把 `hys` 降到 0 之后,暗缝从「常驻」退化成「≤400 ms 一闪」。

**须主人拍板**:24 是既有的调过的值,且降之前应把 U-4 那组抖动用例(±4/260 ms、±2/120 ms、±8/700 ms、正常慢滚进出)整套回归一遍。

### #3 `-0.2` · U-1 暗态语言链在 2× 屏上仍差 AA 一点点(4.36 vs 4.5)

**类型:既有缺陷未完全达标(本轮修法方向对、没够到线)** · 非已拍板项

0.62 → 0.78 **两面都明显改善**,主人点名的两处都已达标:

| 状态 | 0.78 实测(glyph-core p10) |
|---|---|
| 中灰窗 scrollY 8175 / 8167 @1440、8261 / 8253 @1455、11019 @2560 | **6.22:1** ✅ |
| 纯白带 | **9.48:1** ✅ |
| 暗态首屏大标题处 | **4.36:1** ❌(AA 需 4.5) |

暗态那一处的根因是**结构上的天花板**:0.64 暗色磨砂压在纯白字上,底板最亮只能到 `0.64×12 + 0.36×255 ≈ 100`;白字 @0.78 压 100 的算术上限就是 **4.38:1**,不管怎么调滚动位置都过不了 4.5。逐帧扫描(1440 / 1455 / 2560,y 从大标题进条到出条,步长 2–6 px)worst 稳定落在 4.36,vi / zh 同型。

**严重度要如实说小**:这是 **DPR 2 才出现**的亚像素边缘 —— 同一处 DPR 1 最差 **7.71:1**,DPR 2 的芯**中位数也有 7.21:1**,只有最亮 10% 的芯像素踩线,窗口约 25 px 滚动距离。字并不难认,是严格 WCAG 算术差 3%。

**修法(参数级)**:`.lang a { opacity: .82 }`。**实测**:同一最差窗口 0.80→4.48、**0.82→4.61** ✅、0.86→4.87;0.78 与 0.82 肉眼无差。

### #4 `-0.2` · 844×390 横屏,首屏自己的下载行也在折叠线下

**类型:新增缺陷(B2 调参未覆盖横屏)** · 非已拍板项(B2 拍板的是「底空 220」这个值,不是横屏该不该看得见)

`.dl-wrap` 在 844×390 下 top=401 / bot=445,视口高 390 → **整行在折叠线下**。B2 当时校准的是 1366×673 / 1440×700 / 1536×774 三档笔记本高度,横屏手机不在那组里。叠加扣分 #1,**横屏访客首屏与菜单两个下载入口都要滚动才看得到** —— 这是站上唯一的转化动作。

**修法(参数级)**:只在矮视口收底空,不动桌面的 220 —— `@media (max-height: 520px) { .hero { padding-bottom: max(60px, calc(120 * var(--u))); } }`。

**须主人拍板**:220 是主人定过的值;这里只建议**加一条矮屏分支**,不改原值。若判定横屏手机不在覆盖范围内,本条可撤。
