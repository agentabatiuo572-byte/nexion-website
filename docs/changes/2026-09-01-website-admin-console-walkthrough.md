### P1-2 🔴 审计日志加载失败时,同屏印出「没有匹配记录」——把「取不到」画成了「没发生过」

- **页面**:`/audit`。
- **现象**:`GET /api/audit` 失败时,页面同时显示「加载失败 重试」和「没有匹配记录」。
- **复现**:登录 → Playwright `ctx.route('**/api/audit**', r => r.abort('failed'))` → 打开 `/admin/audit`。实测 `bothShown=true`,空态元素 `<p class="kv" style="padding: 8px;">没有匹配记录</p>` 与红条并存。截图 `audit-err.png`。
- **影响**:审计日志是 append-only 的追责面,这里最不能出现的一句话就是「没有记录」。运营在排查「谁改了什么」时看到它,会得出与事实相反的结论;而红条在页面另一处、字号 11.5px、对比度 2.8:1(见 P1-4),很容易被忽略。同一个反模式在驾驶舱是被明确防住的(「实时查询失败则今日列显示『—』+ 重试,**不把失败画成 0**」),审计页漏了。
- **根因**:`admin/src/pages/audit.tsx:33` —— `catch { setErr(true); if (!append) setRows([]); }` 把失败写成空数组,于是 `:64` 的 `rows.length === 0` 分支命中 `:65` 的「没有匹配记录」。失败态应让 `rows` 保持 `null`(或用 `err` 短路空态分支)。

### P1-3 🔴 版本表 `LIMIT 30` 静默截断:**线上版本那一行会整个消失**,而标题写着「只增不删」

- **页面**:`/publish`。
- **现象**:库里 46 个版本,表格只渲染 30 行(v55→v26),**线上的 v8 不在表内**。无分页、无「共 46 个版本」提示、无「加载更早」按钮(审计页有,发布页没有)。

- **影响**:三层:① 唯一能看到「线上是哪一版、为什么上的」的地方,恰恰把线上那一行弄丢了;② 标题「只增不删」与眼前的截断直接冲突,运营的合理推断是「有人删了历史版本」——而那正是 PRD ④ 明令禁止的动作;③ `publish.tsx:209` 用 `st.versions.find(v=>v.status==='live')?.id ?? 0` 判失败面,live 落在 30 条之外时退化成 `0`,判据跟着失真。

- **注**:r6-P2-14 已指出 `LIMIT 30`,本轮补的是**实景后果**(线上行消失 + 无任何截断提示)。
