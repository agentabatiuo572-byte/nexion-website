## 方法

- **量法**:Playwright(借 `Nexion-uniapp` 依赖)。静态几何用 `reducedMotion:'reduce'`;
  动画期用 rAF 页内埋点逐帧记(不用 `page.evaluate` 轮询——见下方勘误)。等 `document.fonts.ready`。
- **口径**:1440 画布、1455 视口(zoom=1)为主,另跑 390 / 768 / 1024 / 1200 / 1439 / 1920。
- **排印普查**:9 条路由全量遍历「带直接文本的元素」,记 `font-size / line-height / letter-spacing /
  font-weight / font-family / color / text-transform / 盒几何`,共 901 条,再按「字号档」聚合成尺子表。
- **亮区**:一律 DOM/计算样式判定;需要像素时用「废 canvas」配方(`#x-bg` 的 `getContext` 返回 null)
  并回看确认未被强制暗色(产物纸面实测 242,242,242,未反转)。暗区截图直接可信。
- **对比度**:白字/黑字按 alpha 合成到**实测地色**上算 WCAG 比值;粒子相关的一律**藏起文字量地色**,
  连采 50–70 帧取最差,不用单帧。
- **新旧分离**:R45 全部改动仍在工作树未提交,故 `git diff` 即 R45 的精确增量;
  每个扣分点都回 diff 核过「是本轮新增,还是既有值」。

### 勘误(自证伪,记录以免误导)

## 扣分清单

### P1-1 · 文章页转化键的箭头几乎不可见(新增缺陷)

- **类型**:新增缺陷。非拍板项、非待拍板项。
- **根因**:R45 随「相关文章」块新增了 `LearnArticle.astro` 的作用域规则
  `.arr { color: var(--x-ink-dim); }`(意图是相关行的 `→`)。同组件里的 `.xbtn.solid` CTA
  内也有三个 `<span class="arr">→</span>`,Astro 作用域把它们一并命中。
- **证据**:
  - 计算样式:`/learn/getting-started/` CTA 底色 `rgb(158,220,29)`、标签 `rgb(10,10,10)`、
    **箭头 `rgba(255,255,255,0.62)`**;同一按钮在 `/nex/` 上箭头是 `rgb(10,10,10)`。
  - 算值:0.62 白合成到柠檬上 = rgb(218,242,169),对底 **1.36:1**(标签为 19:1)。
  - 截图对照:`cta-guide.png`(箭头发白)vs `cta-nex.png`(箭头纯黑)。
  - 覆盖面:6 篇 × 3 语 = **18 页**,三语逐页复核箭头色全为 `rgba(255,255,255,0.62)`。
- **修法**:`LearnArticle.astro` 的 `.arr` 收窄到相关行——`.row .arr { color: var(--x-ink-dim); }`。
  CTA 箭头随之回到 `currentColor` = `--x-on-accent`。

### P1-2 · 页脚版权行掉到 1.24:1(新增缺陷)

- **类型**:新增缺陷。**「页脚透底 + 信息列护字层」是拍板项,本条不动那个决定**——
  破的是决定的**落地范围**:`.info::before` 只包 `.info`(披露段 + 法务链),
  `.copy` 是 `.info` 的兄弟,在护字层之外。R30 之前页脚是实底,该行本来是安全的;
  B1 撤掉实底后没有补上它。
- **证据**:藏文字量地色,70 帧连采(`/` 与 `/zh/` 各一轮):
  **70/70 帧低于 AA 4.5:1**,最差 **1.24:1**,逐帧最差的均值 1.68:1。
  同一时刻受保护的披露段是 6.26:1。截图 `footer-copy-streak.png`(暗区,可信)。
  不是偶发流光,是版权行 1360px 跨度上**恒有**一段压在粒子束上。
- **修法**(与既有护字层同配方,只是局部化):
  ```css
  .copy { position: relative; width: fit-content; }
  .copy::before {
    content: ''; position: absolute;
    inset: calc(-14 * var(--uc)) calc(-24 * var(--uc));
    background: rgba(12, 12, 13, 0.9);
    filter: blur(calc(14 * var(--uc)));
    z-index: -1;
  }
  ```
  `width: fit-content` 是必需的:不加则护字层铺满 1360,在透底页脚上会变成一条可见暗带。

- **证据**:50 帧连采,藏文字量地色:

### P2-1 · `/nex/` FAQ 宣称与首页 FAQ 同规格,三项没跟上(新增缺陷 · 改动未落全)

本轮 diff 把 `min-height 56→60`、`gap 16→clamp(14,2vw,28)`、`idx 色与 28→30`、
`q 500→400`、补 `-0.02em`、补 `text-wrap:balance` 全对齐了,注释写「与首页 FAQ 同规格」。漏了三项:

| 项 | 首页 FAQ | `/nex/` FAQ |
|---|---|---|
| 行线 | `border-top` 逐条 + 末条 `border-bottom`,**`--x-line-dark` = 0.23** | 只有 `border-bottom`,**`--x-line-soft` = 0.10** |
| 收口语法 | 列表**上下都封口** | 首条**无上线**(开口) |
| 答案栏宽 | `max-width: 760` | `max-width: 680` |
| `.q` 字号公式 | `max(18px, 24·--u)` | `clamp(16px, 1.7vw, 24·--uc)` → 390 上 **16 vs 18** |

- **证据**:计算样式 `1px rgba(12,12,13,0.23)` vs `1px rgba(12,12,13,0.1)`;
  实测答案宽 760 vs 680;跨断点表见 §G。截图 `faq-home.png` / `faq-nex.png`——

  ```css
  .faq { border-top: 1px solid var(--x-line-dark); }
  .faq:last-of-type { border-bottom: 1px solid var(--x-line-dark); }   /* 删掉原 border-bottom */
  .faq > p  { max-width: calc(760 * var(--uc)); }
  .faq .q   { font-size: max(18px, calc(24 * var(--u))); }
  ```

### P2-2 · PoC 手风琴的「+」没收口到右缘(新增缺陷)

- **类型**:新增缺陷。R45 本轮把 PoC 改成「记号在右、与 FAQ 同语法」,同时给记号加了 `flex: 0 0 12`。
- **证据**(Range 量字形盒,非元素盒):

  - 截图 `poc.png` 可见「+」与右缘间有一段空隙,`faq-home.png` 则齐。
- **修法**:
  ```css
  .poc .mark { position: relative; }            /* 删 flex: 0 0 calc(12 * var(--uc)) */
  .poc summary { gap: clamp(14px, 2vw, calc(28 * var(--uc))); }
  .poc p { margin: 0 0 calc(20 * var(--uc)); }
  ```

### P2-4 · 本轮新块之间的内部节奏没统一(新增缺陷 · 小)

同一组件里三块相邻纸面板、以及本轮刚定的内页体例,留了几处 2px 级残差:

| 面板竖内衬 | `.toc` / `.related` **24** | `.prose` **34** |

### P3-1 · 404 三块并列结构里只有一块是实心键(新增缺陷 · 口味边界)

- **类型**:新增缺陷,但属**刻意写死**的选择(`class:list={['xbtn', { solid: i === 0 }]}`),故只报不判死。
- **证据**:三块 en/vi/zh 在字号、行距、块距(204/204)、块内 gap(16)上**完全平行**,
  唯独按钮:en 为 `xbtn solid`(柠檬实底黑字),vi/zh 为 `xbtn`(0.16 描边幽灵键)。
  平行结构里只用**一个**属性打破平行,读起来更像疏漏而不是层级。
- **修法**(二选一,建议前者):① 三块统一 `solid`,层级交给顺序;
  ② 若确实要抬 en,层级要落在不止一个属性上(如 en 块加 `x-label` 前缀行或加大块距)。
  另:若面向越南优先,首块语言顺序值得主人拍板(内容决定,非工艺)。
