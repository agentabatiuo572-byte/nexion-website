## 2. P1-9 A/D 只在 height=900 跑 → **已修**

`gate-render-fit.mjs:530-568` 改成:每条路由先在 `widths[0]` 与 `widths[last]` 两档宽下遍历全部高度档,版式指纹变了才算「高度敏感」;敏感路由在每档宽下按指纹去重加扫。实跑输出 `判据 A 实扫 780 次(3/33 条路由对视口高敏感)` —— 3 条正是三语首页(只有它们有 `.hero`,高度断点在 `HeroSection.astro:202,221`)。数目对得上。

两个**判据层面的残留缺口**(今天不咬人,写下来是因为它们是同一族):

- **指纹只由字号构成**(`fingerprint = k:v.fs`,:512)。一个只改 `line-height` 或 `padding` 的高度断点会产生完全相同的指纹 → 路由被判「不敏感」→ 那些高度档 A 一次都不扫。而 A 判的恰恰是行间。今天仓里所有 `max-height` 规则都同时改了字号,所以没有活样本。
- **敏感性探针只取最窄与最宽两档宽**(:534)。形如 `(min-width:861px) and (max-height:520px)` 的规则在 320 和 1920 两档下都测不出变化 → 整条路由被判不敏感。今天没有这种规则。
- `SCAN_SIZES` 跳过 0 尺寸元素,所以**抽屉菜单的高度分档(28/24 两档字号)永远无法把路由染成敏感** —— 与 P1-8 是同一个洞。

## 6. 新判据 E(弹层装得下)—— 审它本身

**做对的**:弹层从 DOM 枚举不写清单;四个量一起判(`overY`/`overX` 内溢 + `offBottom`/`offRight` 出视口),阈值 1px;开不起来记成观测面缺口判红而不是当没问题;实跑覆盖 3 路由 × 200 档视口。我独立开弹层量四边,320×360 / 390×844 / 740×380 / 1920×360 / 2560×900 全部 `top≥0, left≥0, bottom≤0, right≤0, overY=0`,与门的结论一致。

**判据缺口三条**:

1. **开启件仍靠手写清单封开放集合**(:327 `document.querySelectorAll('[data-src]')`)。门头写「弹层从 DOM 枚举(不列清单)」—— 弹层不是清单,**开启件是**。而且失败模式是**假绿不是判红**:找不到开启件就退回 `showModal()`,门自己的注释(:326)承认那样「会量到一张空图」,空图必然装得下 → 记不进 blind、直接过。今天只有 `.cert-zoom` 一个弹层、`[data-src]` 有 2 个,能开(实测 `opened via [data-src]: true`),所以没暴露。
2. **只量右下两边,不量左上**(:346-347 各自 `Math.max(0, r.bottom-innerHeight)` / `r.right-innerWidth`)。弹层顶出视口上缘或左缘时得 0 分。今天 `.cert-zoom` 有 `max-height: calc(94vh / var(--x-zoom))` 兜着,实测 `top` 最小是 0,不咬人。
3. **只认 `<dialog>`**(:338 `querySelectorAll('dialog')`)。全屏固定层的 `.menu`(`SiteNav.astro:350` `position:fixed; inset:0`)是标准的「打得开、可能装不下」件,不是 `<dialog>` → E 一次都测不到它。这正是 P1-8 那个洞的另一面。

**建议**:开启件的发现改成「点遍所有 `button`/`[aria-haspopup]`/`summary` 直到某个弹层开」,或者至少把「退回 showModal」记成观测面缺口而不是当成正常测量;补 offTop/offLeft;把判据的对象从 `<dialog>` 扩到「开启后 `position:fixed` 且覆盖视口的层」。
