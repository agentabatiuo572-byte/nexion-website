## 方法

- Playwright(借 `Nexion-uniapp` 依赖),Chromium **带经典滚动条**跑(`ignoreDefaultArgs:['--hide-scrollbars']`),`deviceScaleFactor:1`,`colorScheme:dark`。
- 主量点 **1455×900 视口**:两站在此都得画布 1:1(我方 `clientWidth=1440` → `zoom=1`;参照站 `scale=1455/1440=1.0104`)。
  另探 1200 / 1280 / 1439 / 1440 / 1441 / 1600 / 1920 / 2200 / 2560 宽,以及 768 / 900 / 1100 / 1300 高。
- **口径校正(重要)**:参照站是 `transform: scale()` 缩放,`getComputedStyle` 返回的是**画布原值**、`getBoundingClientRect` 返回的是**屏幕值**。
  故本报告对参照站:**几何 ÷1.0104,排印值(font-size / letter-spacing / line-height / padding)原样取**。我方 zoom=1,两类读数都是画布值,直接可比。
- 动效判据**未开** `reducedMotion`(单独一档专测降级);滚动一律 `mouse.wheel`(Lenis);等 `fonts.ready`。
- 亮区块不做像素判断,一律走 DOM / 计算样式;需要看亮区实景时用「废 canvas」配方(`addInitScript` 令 `#x-bg` 的 `getContext` 返回 null)并回看。
- 动效参数不靠肉眼:用 `document.getAnimations()` 抓 duration / delay / easing,用 `transitionstart` 事件的 `timeStamp` 抓逐行错拍。
- 粒子织体用**色相无关**指标:把像素折成 `α = max(R,G,B)/255`(两套配色的主通道满值都约 219),再量扫描线上的峰数、峰间谷底、谷/峰比。两站各测两次,数值逐位复现。

### D1 · 粒子丝线的「刻痕」只有参照站的一半 —— 严重度 中高 · 类型 ②

- **实测**:谷/峰比 0.343–0.436(参照站 0.142–0.264),即丝间黑度不足一半;α>0.10 连通段在上半部宽 34.8px(参照站 3.7px),丝线并成宽带;α>0.60 的亮芯覆盖 0.25%(参照站 0.56%)。峰数 61/81/106/104/90/48 对参照站 58/80/102/103/87/45 —— 根数是对的,**只是丝与丝之间没有拉开**。
- **实景**:`scratchpad/ref-hero.png` vs `our-hero.png`,左上叶与下叶最明显 —— 参照站是丝丝分明的金属丝网,我方是一层发光织物。
- **可能杠杆(未证伪,建议先做 A/B)**:`src/scripts/fx.ts` 的辉光离屏 —— `gctx.filter = 'blur(7px)'` + `gctx.globalAlpha = 0.85`。首屏位姿 `poseHome` 的 `scl = min(W,H)/44` 下丝距约 4px,7px 模糊足以把相邻两丝之间填平;这也解释了为什么疏处(0.75 线)差距最小、密处(0.20 线)差距最大。
- **参数级修法(任一或组合,建议按此顺序试)**:① 模糊半径 7 → 3;② `globalAlpha` 0.85 → 0.45;③ 让半径随位姿的 `scl` 走(密位姿细、疏位姿粗)。改完用本报告同一把尺复量谷/峰比,目标带 0.15–0.27。
- **归属**:辉光层是 R32 的既有实现,主人看过多轮渲染 → **属既有值,须主人拍板**,不由评审授权修改。
