1. 新增授权后的只读发布能力探针，检查新版检查表、索引和全局任务状态。缺表时返回明确的升级提示；保留旧任务心跳及收尾通道。

## 在完整仓库应用

先确认工作树干净且与审查基线兼容，然后应用补丁：

```sh
git switch -c fix/publisher-upgrade-recheck
git am /path/to/0001-fix-publisher-upgrade.patch
```

`git am` 在完整仓库中会生成对应的真实修复提交，其 SHA 不必等于上述本地诊断提交。若文件已被其他提交修改，先处理补丁冲突并重新测试，不使用强制覆盖。运行修复说明中的完整回归，随后由具有仓库写权限的身份正常推送修复分支。

首次更新若原 API 尚不支持新探针，启动器会拒绝猜测其状态。应先确认原发布已结束或完成恢复，再受控重启本仓服务；不能删除数据库或任务锁来“解除灰色按钮”。生产迁移和部署仍由既有维护流程完成。
